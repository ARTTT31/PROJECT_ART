# Deployed Verification

These items stay open for months whenever nobody writes down what the live environment answered.
`docs/internal/status.md` §4 tracks them; this skill is how each one gets closed.

**Not this skill:** running `pytest`, `vitest`, `tsc`, `eslint`, `next build` or `alembic check` locally
— that is `verification-before-completion`. **Not this skill:** guessing. A check you could not run is
reported as "not run", never as "looks fine".

## Setup

```bash
FRONTEND=https://<frontend-origin>     # the Vercel deployment; do not commit it to the repo
BACKEND=https://<backend-origin>       # the Render service URL
```

The origins come from the platform dashboards, not from a hardcoded value in the repo (README rule).

## 1. Health and readiness

```bash
curl -s -o /dev/null -w '%{http_code}\n' "$BACKEND/health"        # expect 200
curl -s "$BACKEND/health" | head -c 400                          # expect database.status: ok + latency_ms
curl -s -o /dev/null -w '%{http_code}\n' "$BACKEND/health/ready" # expect 200; 503 means the DB is down
```

`/health` always answers `200` on purpose (uptime monitors) — a `degraded` body is the real signal, so
read the JSON, not just the code. The platform health check should point at `/health/ready`.

## 2. Migration head actually applied

Render runs `alembic upgrade head` as `preDeployCommand`. Confirm in the deploy log that it ran **before**
the service restarted, then:

```bash
cd backend && DATABASE_URL="<production URI>" ./venv/Scripts/python.exe -m alembic current
```

`current` must show the same revision as `alembic heads` locally. Two owners of the schema is how a
column goes missing while CI stays green.

## 3. Frontend CSP

```bash
curl -sI "$FRONTEND/login" | grep -i 'content-security-policy'
```

Expected after the P4 fix: `script-src 'self' 'sha256-…'` with **no** `'unsafe-inline'`, and `img-src`
without a blanket `http:`. Then load `/login` and `/dashboard` in a browser and confirm there is no
`Refused to execute inline script` error and no theme flash (the theme must be set before first paint).

## 4. WebSocket origin

The client prefers `NEXT_PUBLIC_WS_URL`, then `NEXT_PUBLIC_API_URL`, then its own origin. Open the
deployed app signed in, DevTools → Network → WS:

- the connection to `/api/v1/ws/notifications` answers `101`;
- there is no repeated reconnect loop and no `1008` close (a `1008` means the handshake was not
  authenticated — check the cookie is sent cross-site);
- a notification generated by the app arrives on that socket.

If the `/api` rewrite answers plain HTTP but drops the upgrade, set `NEXT_PUBLIC_WS_URL=wss://<backend>`
on Vercel — the session cookie is already `SameSite=None; Secure`, so it is sent cross-site.

## 5. Email delivery (`EMAIL_BACKEND`)

From the deployed origin: register a throwaway account, then use "forgot password" and confirm the mail
arrives (and that the link resets the password and revokes sessions). A `200` from
`POST /auth/forgot-password` proves nothing on its own — the endpoint answers identically by design.
Check the Render environment actually holds the SMTP/API values; a missing backend degrades silently.

## 6. Shared rate-limit buckets (only when running more than one instance)

With `SLOWAPI_STORAGE_URI` pointed at Redis, alternate requests against two instances and confirm the
counter is shared (five failures then `429`, regardless of which instance answers). If the deployment is
single-instance, record that this check does not apply and keep the process-local `[SCALING]` notice.

## Recording the result (the part that gets skipped)

1. Paste the literal output — the status code, the CSP header, the revision hash, the mail that arrived.
2. Remove the item from `status.md` §4 (or mark it verified with the date), and append a `changelog.md`
   entry: date, commit sha, origin, what was run, what it printed.
3. Never write "verified" for an item you could not reach. Say which origin was unavailable.

## Done when

- Every item touched has a captured response in the changelog entry.
- No item was closed on inference ("the code looks right").
- `status.md` §4 shrinks; nothing was added to it without a reason.
